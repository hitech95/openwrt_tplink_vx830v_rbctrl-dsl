# FOSS voice link: as-built design

**Current implementation: Rust workspace [`rbctl-feed/rbctl-voip`](../../rbctl-feed/rbctl-voip/README.md).** The C prototype was retired after [hardware parity](test-report.md#m21-closure); the Rust tests retain 163 byte-for-byte golden vectors. M3 embeds the generated C ABI.

**Integration pattern (unchanged from the C design):** one owner/event loop; `Link::request` for DD01, feed every frame to `Link::receive`, call `Link::tick` at `Link::deadline()`, drain `Link::pop` after every receive (also on error). The transport is passed per call (`&mut impl Transport`), so the link never holds callbacks. The C ABI wraps the same object behind an opaque handle and a send callback.

**Behaviour changes vs the C prototype:** none on the wire (golden vectors). API-level: `Link::abandon()` drops a pending request while keeping learned MACs, sequence and queued events (the C CLI re-initialized the whole link, resetting the control peer to broadcast); DSP bodies are a typed enum, and encoding rejects a body that does not match the command's layout.

# C prototype: libvx830v-voice (M1.1, historical)

The following API and CMake instructions describe the retired prototype. Its public header was `<vx/voice.h>` and its shared library was `libvx830v-voice.so.0`. For current builds and handset commands see the [Rust workspace README](../../rbctl-feed/rbctl-voip/README.md).

## Event-loop integration

The first M2 diagnostic CLI used this loop for `init` and `events`.

1. Initialize one `vx_link` per board with the local MAC and a synchronous frame-write callback. Check `vx_link_init` for an entropy error before using the link: each session starts with a random DD01 sequence. For deterministic OEM replay, `vx_link_init_seeded(..., 0)` starts at sequence 1. `vx_packet_open` binds a nonblocking Linux `AF_PACKET` fd to the configured **VLAN subinterface**. Its kernel filter drops `PACKET_OUTGOING` and selects the three voice EtherTypes; the receive engine checks destination, source and marker.
2. Start one `vx_request` at a time: `NULL,0` body for `1a/1b`, exactly 132 bytes for `16`. Initial transmission is immediate. On a monotonic millisecond clock call `vx_tick` at `sent_ms + interval` while `request_len` is nonzero. Each expiry retransmits the saved frame or, after the last response interval, returns `-ETIMEDOUT`. The [documented limits](board-link.md) apply to supported requests. An overlapping request returns `-EBUSY`. On an idle link `1c` returns `-EOPNOTSUPP` without sending or consuming a sequence: this peer has no handler.
3. On fd readability, pass each complete `vx_packet_read` result to `vx_receive`. A valid DD01 completion must match the peer, subtype, sequence and four-byte body. Only then is the control MAC learned. Success returns `VX_CTL`; `-EREMOTEIO` carries the original BE32 status in `peer_status`. Send failures propagate and end the pending request. `-EAGAIN` is unrelated traffic; a bad frame does not cancel a request. Readiness still requires the appropriate async DSP results.
4. On `VX_EVENT`, drain `vx_pop` until `-EAGAIN`. The FIFO holds 15 raw records. Status zero means **enqueued**, one means too short, two means queue full. Only the last successful enqueue is cached by source+sequence, even if its ACK send failed. A retry of a rejected event is evaluated again and can succeed once space is available. The stock peer's response to a nonzero status remains a hardware question. Drain pending events even on send error.
5. On `VX_MEDIA`, use `vx_media_decode` on the returned view to borrow the slot, selector and original RTP/RTCP datagram. Copy before reusing the receive buffer. `vx_send_media` uses independent media MAC discovery, sequence zero and selector 3/4. A control completion never changes the media destination. See [peer.md](peer.md) for IPv4 loopback substitution on the board.

Serialize calls through one owner/event loop. A send callback must consume or copy the buffer before returning and must not reenter the link. Reinitializing the local link discards its pending requests, queued events, learned MACs and ACK cache; it does not clear the peer. T2.8 verified the CLI's exclusive-owner warm path: attach state 0 → RTP_OFF and CHANNEL_CLOSE for all slots → SLIC and DSP defaults → CHANNEL_DEFAULT ×4. DSP_START is reserved for stopped state 1 and requires a fresh DD02 completion. See [live restart results](test-report.md#m2-live--2026-11-25-t28-master-restart-pass).

## Wire and record API

**M2/M3 caller requirements:**

- Queue pending DSP commands in order above `vx_link`; dispatch the next only after completion or explicit failure handling. A lost `16` uses three 300 ms response intervals (900 ms total with timely ticks, longer if the loop stalls).
- A `16` status of zero can also mean the **peer** dropped a command from a full queue. For SLIC/DSP startup, advance only on the corresponding DD02 result with a separate deadline. For commands without a completion event, do not infer applied state solely from the ACK.
- Keep full identity strings in account/UCI settings. When formatting board CID for T2.4, limit name and number separately to the peer's **15-byte** copies; do not split a multibyte character. Verify truncation and the handset character repertoire with synthetic identities before finalizing formatting policy.

`vx_frame_encode/decode` operate on bounded untagged Ethernet frames (standard 1500-byte MTU). CRC covers just the zero-CRC header and declared body. Controls are zero-padded to 60 bytes. Structural decoding accepts either marker; a master link only admits `0x10` from the peer. Integers are serialized bytewise, never through a packed native struct.

`vx_dsp_encode/decode` convert between `struct vx_dsp` and the fixed 132-byte record. Fields are host-order integers or exact-width byte arrays. Clear the struct first. For scalar commands supply `u.words[]` in the order in the [inventory](board-link.md#inner-dsp-inventory); for CHANNEL_OPEN the eleven words follow the [channel layout](controller-startup.md#channel_open-body-0x2c-meaningful-bytes). CID, tone and RTP have named layouts. Write IPv4/IPv6 as network-order octets, ports as host integers, and `family` as 2 or 10: it is always emitted BE32. Family encoding is supported independently of IPv6 interoperability. DSP codec selector and RTP payload type are separate fields. Use zero for unspecified words in new messages. Callers choose dial policy, CID field selection, ring mode, locale and slot; the wire codec does not inspect strings or generate analog signalling.

The `event` argument selects the event layout for DTMF_END (2 words vs the 3-word TX helper) and FXS_STAT_GET (opaque stats response vs slot request). For named-only IDs 9, 14, 74 the union exposes all 128 bytes unchanged; it does not invent a meaningful body length. ID 94 and unlisted gaps return `-EOPNOTSUPP`. Known-field decoding discards reserved bytes; an application needing exact relay bytes should retain the original record.

## Offline verification

See also the [M2 board-leg settings](#m2-board-leg-settings) for the live media configuration.

Ordinary host builds do not require lint tools. With the default settings, CMake names missing tools at configure time and the corresponding targets print `SKIP` when invoked. For CI or a T1.9 result, use `VX_REQUIRE_LINT_TOOLS=ON` as below: configuration then fails if any tool is missing. A partial lint run is not a T1.9 pass.

From `voip-feed/vx830v-voip`:

```
cmake -S . -B build -DVX_BUILD_TESTS=ON
cmake --build build
ctest --test-dir build --output-on-failure
cmake -S . -B build -DVX_REQUIRE_LINT_TOOLS=ON
cmake --build build --target lint
python3 -B tests/qemu/diff.py
CC=clang cmake -S . -B build-san -DVX_SANITIZE=ON -DVX_BUILD_TESTS=ON -DVX_FUZZ=ON
cmake --build build-san
ctest --test-dir build-san --output-on-failure
cmake --build build-san --target fuzz
```

CMake ≥3.16 builds the project (CTest's `--test-dir` shortcut needs a newer CTest; on older releases run `ctest` from the build directory). `VX_BUILD_TOOLS` is off by default; enabling it alongside tests adds `cli_startup`. `VX_BUILD_MODULES` is reserved. Missing QEMU or OEM rootfs skips only the differential test with exit 77. Tests retain assertions in release builds. `packet_read` substitutes the receive syscall, including Linux packet-type metadata, without opening a socket.

`format` applies the project Linux style; `lint` runs `format-check`, external Linux `checkpatch.pl --no-tree --strict --file`, clang-tidy and cppcheck over the library and C tests. Set CMake cache paths `CLANG_FORMAT`, `CHECKPATCH`, `CLANG_TIDY`, `CPPCHECK` if not on PATH, or supply `KERNEL_SRC` for checkpatch discovery. Tested with LLVM 21 and cppcheck 2.19. Checkpatch exceptions: ISO userspace fixed-width types rather than kernel aliases (`PREFER_KERNEL_TYPES`), libFuzzer's required CamelCase entry point (`CAMELCASE`), and clang-format's continuation indentation for compound literals (`PARENTHESIS_ALIGNMENT`). clang-tidy exclusions cover adjacent same-type wire parameters, intentional octet narrowing, transitive platform headers (`misc-include-cleaner`), and Annex K `memcpy_s`/`memset_s` advice unavailable on musl. Two local annotations cover GNU ld's reserved `__wrap_` spelling and the enum's explicit wire-ID gaps. All other enabled diagnostics fail lint.

The fake transport and explicit clock drive full retry budgets without sleep. The optional Python `tests/peer-emu/peer.py` models DD01 status and last-sequence replay using in-memory or length-prefixed stream frames. It does not model DSP readiness. Differential comparisons build both sides locally and retain no captures or OEM outputs. See the [test report](test-report.md) for the comparison boundary on the final ring word and measured fuzz duration.

## M2 board-leg settings

Configure the stream with **DD01/0x16, DSP command 10 (`RTP_ACTIVE`)**. Offsets below are hexadecimal, relative to the DSP body (after the command word). The CLI uses the following profile for its two-way PCMA loop:

| Offset | Wire encoding | Value and purpose |
|---|---|---|
| `00` | BE16 | `0xfffe`, the activation argument used in the OEM fixture. |
| `10`, `14` | BE32 each | Slot 0 or 1; direction **3** for send/receive. Direction 0 is **none**, not “use default.” Wire 1/2 map to send-only/receive-only statically. |
| `18`, `1c`, `20` | BE32 each | DSP codec **2** = PCMA; voice RTP payload type **8** for TX and RX. Codec selector and RTP PT are different enums. |
| `28`, `2c` | BE32 each | 20 ms TX and RX: 160 G.711 octets per 8 kHz interval, nominally 50 RTP packets/s per slot. |
| `30`, `34`, `38` | BE32 each | DTMF mode **1**, TX/RX telephone-event PT **101/101** in the audible fixture. Mode 1 enables relay, with TX PT 0 falling back to 96. PT 101 is a fixture choice, not a speech prerequisite or a fixed network-side PT. |
| `74` | BE32 | **2** (IPv4). Both test addresses are loopback; the peer rewrites IPv4 endpoints to its own per-slot relay ports. |

**DD03/0x19 is the data path.** Its body is `BE16(slot), BE16(selector), datagram`; selector **3** carries RTP, **4** RTCP. The activation direction and DTMF flags are *not* in each audio frame. The loop changes the destination slot and preserves the entire RTP/RTCP datagram (including its payload type, sequence and timestamp).

The [controlled comparison](test-report.md#m2-closure) reproduced the effect of changing direction alone on **RTP packet flow**. The [earlier T2.6 run](test-report.md#m2-live--2026-11-25-t26-two-way-voice-pass) separately established audible two-way speech with the full fixture profile above. See [peer.md](peer.md#t26-follow-up-media-direction-vs-telephone-event-settings) for the ADAM/kernel translation and limits of the RX telephone-event evidence.
